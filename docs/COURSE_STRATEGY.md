# 课程策略引擎

课程策略位于用户目标与课程各个 Agent 之间。它不是一套固定模板，也不是在提示词里增加“考试多出题、工作多讲原理”，而是统一回答五个问题：

1. 学完后，什么可观察证据能证明目标已经达成？
2. 为获得这些证据，学习者必须建立哪些能力与知识连接？
3. 当前内容的难点究竟来自哪里？
4. 应使用什么资料、教学动作与练习进行验证？
5. 哪些内容必须加入、作为扩展，或明确略过？

## 核心原则

### 先定义证据，再生成内容

每门课程先定义 `targetEvidence`。大纲、小节、课堂和练习都必须能追溯到至少一项证据，不能因为某个知识点常见就自动加入。

### 先建能力图，再排章节

课程同时执行两种检查：

- 正向检查：当前内容是否自然通向下一项能力；
- 反向检查：最终目标依赖的基础、工具、桥梁、应用和检验节点是否齐全。

### 难度是向量，不是星级

统一使用七个难度维度：

- `recognition`：能否识别当前问题属于哪一类；
- `concept`：是否理解定义、机制与必要条件；
- `procedure`：能否稳定执行方法或步骤；
- `calculation`：运算量、细节和精度负担；
- `transfer`：能否迁移到变化后的题目或任务；
- `diagnosis`：能否定位错误、故障或失效条件；
- `tradeoff`：能否比较方案并解释取舍。

章节星级只用于浏览，具体教学必须指出主要难度来源。

### 方法必须带边界

每条常规方法、原理方法、简便方法或生产方案都要说明：

- 为什么有效；
- 最适合什么情况；
- 使用前提；
- 失效边界、代价或风险。

### 当前知识必须说明未来用途

每个小节都包含：

- `whyNow`：为什么现在学习；
- `futureUses`：会支撑哪些后续题型、任务或概念；
- `successEvidence`：怎样证明已经学会。

这用于发现没有写在章节标题中、却决定后续效率的桥梁知识。

### 支持应随证据逐步撤除

初学者先使用完整示例和显式理由；形成初步能力后，逐步隐藏步骤，转向独立判断、混合辨认与迁移。不能对所有基础水平固定使用同一讲解密度。

### 检索必须有目的

每条检索词都带 `purpose`，只能服务于课程决策。不能对数学课程搜索“当前版本”，也不能对工程课程只搜索概念百科。

### 内容取舍必须可解释

课程范围区分：

- 达成目标不可缺少的内容；
- 很快会复用的高价值桥梁；
- 有价值但受时间限制的扩展；
- 与当前目标弱相关而略过的内容。

“尽量全面”不等于无限堆内容。

## 五种策略模式

### `exam`：考试与认证

目标是在有限时间内识别题型、选择方法、稳定执行并处理变式。

课堂从冷启动辨认开始，说明难点来源，比较稳妥方法、原理方法和简便方法，明确每条路径的条件与失效边界，最后用变式或混合题验证迁移。

主要证据是题型识别、方法选择、条件检查、过程正确、时间效率和变式迁移。

### `work`：工作与真实问题

目标是在真实约束下完成任务、解释决策、诊断失败并验证结果。

课堂从任务或故障开始，建立可预测系统行为的机制模型，完成最小可运行实现，比较方案和约束，通过故障注入、观测和验收标准验证。

主要证据是可运行交付物、设计解释、权衡判断、故障诊断和生产检查。

### `academic`：学术基础与研究

目标是理解定义和假设，能够推导、论证、反驳并连接相关理论。

主要证据是准确表述、推导、证明、构造反例和比较理论。

### `quick-start`：快速入门

目标是用最少必要知识完成第一个可靠结果，并保留正确的深入入口。

主要证据是首次成功、可复现、知道一个常见风险和下一步去向。

### `mastery`：系统掌握

目标是建立完整主干、关键桥梁、多种表示和跨场景迁移能力。

主要证据是解释、应用、比较、诊断和综合迁移。

## 数据模型

```ts
type CourseStrategy = {
  schemaVersion: 1;
  mode: "exam" | "work" | "academic" | "quick-start" | "mastery";
  rationale: string;
  targetEvidence: string[];
  difficultyPriorities: DifficultyDimension[];
  researchIntents: Array<{
    purpose:
      | "scope"
      | "tasks"
      | "dependencies"
      | "methods"
      | "pitfalls"
      | "evidence";
    query: string;
  }>;
};

type SectionStrategy = {
  role: "foundation" | "tool" | "bridge" | "application" | "verification";
  whyNow: string;
  futureUses: string[];
  successEvidence: string[];
  difficulty: {
    primary: DifficultyDimension;
    factors: Array<{
      dimension: DifficultyDimension;
      level: 1 | 2 | 3 | 4 | 5;
      reason: string;
    }>;
  };
};

type LessonLearningDesign = {
  strategyMode: CourseStrategy["mode"];
  whyNow: string;
  futureUses: string[];
  successCriteria: string[];
  difficultyFocus: string[];
  methodPaths: Array<{
    name: string;
    principle: string;
    bestFor: string;
    boundary: string;
  }>;
};
```

## 生成链路

1. 根据用户明确目标确定策略模式。
2. 按带用途的检索意图并行查找资料并去重。
3. 从 `targetEvidence` 反向建立必要知识、工具、桥梁、应用和检验节点。
4. 同时检查覆盖、依赖、后续用途、颗粒度、方法边界、取舍与证据闭环。
5. 课堂读取整门课程结构和当前小节策略，不只读取同章相邻小节。
6. 助教根据模式、难度来源、用户选择与学习证据提供反馈。
7. 练习按识别、理解、应用、诊断和迁移产生可判断证据。

## 压力测试

### 考研数学

课程必须识别“基本初等函数 → 运算与复合 → 反函数 → 双曲/反双曲函数 → 后续积分结构”这类隐含桥梁。双曲函数是否列为必学取决于考试范围和时间，但系统必须给出纳入、扩展或略过的理由。

### Flink 工作课程

课程不能停留在“Checkpoint 是什么”，必须连接状态、一致性、数据源位置、故障恢复、反压与可观测性。完成证据不是背定义，而是能恢复失败任务、解释语义边界并定位一次错误恢复。
